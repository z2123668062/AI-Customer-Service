# 部署故障清单（本地 Docker 阶段）

> 时间：2026-11-17 ｜ 环境：Windows + Docker Desktop 29.2.0 + Compose v5.0.2
> 目的：记录真实撞到的坑、定位层、修复与验证，作为部署排障证据。
> 说明：标注「本机环境」的条目属于 Windows/Docker Desktop 特有，CVM（Linux）上不一定复现。

## 1. Docker Hub 直连失败

- **现象**：`docker compose build` 第一步就失败，无法解析基础镜像。
- **报错原文**：`failed to do request: Head "https://registry-1.docker.io/v2/...": EOF`
- **定位层**：Docker 镜像拉取（网络出口）
- **修复**：镜像源参数化。`deploy/Dockerfile` / `Dockerfile.web` 用 `ARG PYTHON_IMAGE / NODE_IMAGE / NGINX_IMAGE`；本地用 `deploy/.env.docker.local` 指向 `docker.m.daocloud.io`；CVM 换腾讯云镜像即可，Dockerfile 不改。
- **验证**：`python:3.13-slim`、`qdrant:v1.13.6`、`redis:7-alpine` 通过镜像前缀拉取成功；后端镜像构建成功（442MB）。

## 2. `# syntax=docker/dockerfile:1` 拉取 frontend 失败

- **现象**：构建在 `resolve image config for docker-image://docker/dockerfile:1` 处报 EOF。
- **定位层**：BuildKit frontend 镜像
- **修复**：删除两个 Dockerfile 的 `# syntax=docker/dockerfile:1`。当前构建未使用该 frontend 的特有语法。
- **验证**：删除后构建进入正常的 `FROM python:3.13-slim` 流程。

## 3. pip 在 C 盘临时目录失败

- **现象**：干净 venv 安装依赖时报错，`pip check` 无包、`pip freeze` 为空。
- **报错原文**：`FileNotFoundError: [Errno 2] No usable temporary directory found in ['C:\\Users\\...\\Temp', ...]`
- **定位层**：Windows 临时目录（C 盘 95% 满 + 权限）
- **修复**：把 `TEMP`、`TMP`、`PIP_CACHE_DIR` 指到 E 盘（`E:\毕设_记忆系统\tmp`、`pip-cache`）。
- **验证**：同一命令重跑，47 个包安装成功。

## 4. 新建 venv 的 python.exe 写入被拦截（本机环境）

- **现象**：同一个用户、同一 cwd，旧 venv 和 `D:\python\python.exe` 能写 `logs/`，新建 venv 的 `python.exe` 写 `logs/`、`deploy/` 都报 `PermissionError`。
- **定位层**：本机安全策略对新解释器路径的限制（不是目录 ACL，也不是依赖问题）。
- **绕过验证**：用 base Python + 新 venv 的 `site-packages` + pywin32 路径跑 256 测试，全绿。
- **说明**：Docker/Linux 容器内不存在该问题；不修改项目代码。

## 5. Git Bash/curl 传中文 JSON 返回 400

- **现象**：`curl -d '{"message":"你好"}'` 返回 400，nginx 日志 `POST /api/v1/chat/ 400`。
- **定位层**：Windows 终端编码（中文被按非 UTF-8 传给 curl）
- **修复/验证**：用 Python `httpx`（UTF-8）发送，返回 200 并正常流式回复；项目新增 `deploy/smoke_test.py` 作为标准冒烟入口。
- **结论**：服务端无问题，浏览器/Vue 前端不受影响。

## 6. Redis 停机时降级太慢（已修复）

- **现象**：停掉 Redis 后对话不崩（HTTP 200），但触发 30s 超时兜底，用户等待 36s。
- **根因**：`short_term_memory.py` 的 Redis 客户端未设连接超时；Docker 网络里容器停机后连接/DNS 挂起，实测单次 12.76s。
- **修复**：
  1. `config.py` 新增 `REDIS_CONNECT_TIMEOUT=1.0`、`REDIS_SOCKET_TIMEOUT=1.0`；
  2. Redis 客户端传入 socket 超时；
  3. 新增 `redis_call()`，所有 Redis 操作用 `asyncio.wait_for` 硬超时（`short_term_memory` + `explicit`）。
- **验证**：256 测试全绿；停 Redis 后对话 **11s** 完成（正常回复“记住了，小羊”，不再是超时兜底）。

## 7. Qdrant 停机降级（无需修复）

- **现象**：停掉 Qdrant 后语义路报 `Name or service not known`。
- **定位层**：检索语义路（embedding/Qdrant）
- **结果**：retriever 自动降级到结构化/原文通道，对话 15s 完成，注入 7 张卡，HTTP 200。
- **结论**：符合“Qdrant 可选、不可用不阻塞”的设计。

## 8. 后端重启瞬间 nginx 502（预期）

- **现象**：`restart backend` 后立即请求 `/health` 返回 502。
- **定位层**：nginx 反代到尚未监听的后端
- **处理**：等待健康检查（start_period 60s）；`docker compose up` 已用 `depends_on: service_healthy` 保证顺序。
- **结论**：预期行为，非故障。

## 9. node:22-alpine 从镜像源拉取卡死（本机网络）

- **现象**：前端多阶段构建在 node 基础镜像层卡住（30/56MB 后长时间不动）。
- **定位层**：基础镜像拉取（daocloud 对该层限速/卡死）
- **处理**：本机先用 `npm run build` 产出 `web/dist`，用 `deploy/Dockerfile.web.local`（nginx + 已构建 dist）完成本地全链路验证；多阶段 `Dockerfile.web` 留到 CVM 验证。
- **验证**：本机 Vue 构建 205 模块、4.3s；本地 web 镜像 73.9MB，页面与 SSE 正常。
- **待办**：CVM 上验证 `npm ci + npm run build` 多阶段构建。

## 10. 开 Basic Auth 后 web 容器变 unhealthy（已修复）

- **现象**：给 nginx 加 `auth_basic` 后，`docker ps` 里 web 从 healthy 变成 **unhealthy**，其他三个服务正常，公网访问正常。
- **报错原文**：无报错日志；`docker inspect` 显示 `Health: unhealthy`，FailingStreak 持续增长。
- **定位层**：容器健康检查（不是应用层，服务本身完全正常）
- **根因**：`Dockerfile.web` 的 HEALTHCHECK 打的是 `http://127.0.0.1/`，鉴权一开这个请求返回 **401**，busybox 的 wget 对 401 返回退出码 1 → 探针永远失败。
- **修复**：探针改打 `http://127.0.0.1/health`，并在 nginx 里给 `/health` 单独 `auth_basic off`（该路径只返回 `{"status":"ok"}`，不含任何数据）。
- **验证**：重建镜像后 web 回到 healthy；容器内 `wget -qO- http://127.0.0.1/health` → `{"status":"ok"}`，打 `/` → 退出码 1。
- **教训**：加鉴权时，凡是「探针 / 监控 / 负载均衡」走的路径都要显式豁免，否则健康检查会假死，而 `depends_on: service_healthy` 会让前端一起起不来。
