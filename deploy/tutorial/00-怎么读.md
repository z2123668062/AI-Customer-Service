# 00 · 怎么读这份教程

## 先说实话

上一份 `../README.md` 是「总览 + 决策记录」，信息密度太高，不适合第一次学部署的人。
这份教程换个写法：**一次只做一件事，每章都能动手跑出一个结果。**

## 你会做出的东西

按顺序读，最后你会亲手做出这 4 个文件：

1. `deploy/Dockerfile` —— 后端的「镜像配方」
2. `deploy/Dockerfile.web` —— 前端的「镜像配方」
3. `deploy/nginx.conf` —— 对外的「门卫」
4. `deploy/docker-compose.yml` —— 四个容器一起启动的「编排菜单」

## 每一章的结构

- **目标**：这一章结束时，你能看到什么
- **先讲最小版本**：几行代码，逐行解释
- **再对照真实文件**：项目里那几行多出来的是干什么的
- **动手**：在 PowerShell 里执行的命令
- **检查点**：没通过就不要往下读
- **常见错误**：这一步最容易卡在哪

## 四章的顺序

| 章 | 你会做出来的东西 | 你会理解 |
|---|---|---|
| 01 把后端装进容器 | 一个能访问 `/health` 的后端容器 | 镜像、容器、Dockerfile、build/run、端口 |
| 02 把前端和 nginx 装进容器 | 浏览器 8080 能打开页面，`/api` 能通 | 静态文件、nginx、反向代理、容器网络、SSE |
| 03 用 compose 把四个容器连起来 | 一条命令起 backend/web/redis/qdrant | compose、卷、健康检查、环境变量 |
| 04 排障与上 CVM | 能自己定位问题，并把同一套东西放到云服务器 | 排障顺序、CVM、安全组、成本 |

## 开始前

1. Docker Desktop 已启动（左下角 Engine running）。
2. 打开 PowerShell，先到项目根目录：

```powershell
cd E:\毕设_记忆系统\AI-Customer-Service
```

3. 每章的命令都从这里开始执行。
4. 不要背命令。看懂「这一步在干什么」比记住命令重要。

## 卡住了怎么办

把**报错原文**直接发我，不要自己猜。部署的排障 90% 是靠报错定位的。
