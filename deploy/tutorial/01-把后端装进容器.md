# 01 · 把后端装进容器

## 目标

这一章只做一件事：**把 FastAPI 后端装进一个容器，用 `curl` 能访问到 `/health`。**

暂时不碰前端、不碰 Redis、不碰 Qdrant。先把「打包」这件事搞明白。

检查点（做完你应该看到）：

- `docker images` 里有一个 `memory-backend:learn`
- `docker ps` 里有一个容器，状态是 `(healthy)`
- `curl http://localhost:8000/health` 返回 `{"status":"ok"}`

---

## 1. 先写一个最小的 Dockerfile

先不要看项目里的文件，先在纸上/脑子里理解这 8 行：

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements-prod.txt .
RUN pip install --no-cache-dir -r requirements-prod.txt
COPY app ./app
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

逐行解释：

| 行 | 含义 | 什么时候执行 |
|---|---|---|
| `FROM python:3.13-slim` | 以「官方 Python 3.13 精简版」为基础。没有它，容器里连 Python 都没有 | **构建时**，先拉基础镜像 |
| `WORKDIR /app` | 把容器里的工作目录设为 `/app`，不存在会自动创建 | 构建时 |
| `COPY requirements-prod.txt .` | 把宿主机的 `requirements-prod.txt` 复制到容器当前目录 `/app` | 构建时 |
| `RUN pip install ...` | 在构建时执行 pip，把依赖「烤」进镜像 | **构建时**，结果成为镜像的一层 |
| `COPY app ./app` | 把项目里的 `app/` 代码复制进 `/app/app` | 构建时 |
| `EXPOSE 8000` | 声明「这个容器里跑的服务用 8000 端口」。**只是声明，不会自动对外开放** | 构建时（元数据） |
| `CMD [...]` | 容器启动时执行的命令 | **运行时**，每次 `docker run` 都执行 |

两个最容易混的点：

1. **`RUN` 是构建时，`CMD` 是运行时。**
   `RUN` 在 `docker build` 时执行，结果写进镜像；`CMD` 在 `docker run` 时才执行。
2. **`EXPOSE` 不等于 `-p`。**
   `EXPOSE 8000` 只是告诉别人「我用 8000」；真正把端口开到宿主机，要靠 `docker run -p 8000:8000`。

还有一个顺序问题：**为什么先 COPY requirements，再 RUN pip，最后才 COPY app？**

因为 Docker 构建是**分层缓存**的。只要 `requirements-prod.txt` 没变，pip 这一层就直接用缓存；你只改代码时，只有 `COPY app` 之后的层需要重建。反过来写（先 COPY 全部代码再 pip），改一行代码就会重装所有依赖。

## 2. 对照项目里的真实 Dockerfile

打开 `deploy/Dockerfile`。最小版本之外，它多了 4 块东西：

### ① 构建参数（为了国内网络）

```dockerfile
ARG PYTHON_IMAGE=python:3.13-slim
FROM ${PYTHON_IMAGE}

ARG PIP_INDEX_URL=https://pypi.org/simple
```

- `ARG` 是「构建时可以传进来的变量」。
- 默认还是官方源；国内拉不动时，用 `--build-arg` 换成镜像站。这样 Dockerfile 本身不用改。
- `RUN pip install` 里也用了 `${PIP_INDEX_URL}`。

### ② 环境变量

```dockerfile
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1
```

- `PYTHONUNBUFFERED=1`：日志立刻输出，不会卡在缓冲区里（`docker logs` 能看到实时日志）。
- `PYTHONDONTWRITEBYTECODE=1`：不生成 `.pyc` 垃圾文件。
- `PIP_NO_CACHE_DIR=1`：镜像里不留 pip 缓存，体积更小。

### ③ 非 root 用户

```dockerfile
RUN useradd --create-home --uid 10001 --shell /usr/sbin/nologin appuser \
    && mkdir -p /app/data /app/logs \
    && chown -R appuser:appuser /app

COPY --chown=appuser:appuser app ./app

USER appuser
```

- 默认容器里是 root。万一应用被攻破，攻击者就是 root。
- 这里创建一个 UID 10001 的普通用户 `appuser`，把 `/app` 的属主给它，然后 `USER appuser` 切换过去。
- `COPY --chown` 表示复制进去时顺便改属主，否则文件还是 root 的，appuser 读不了/写不了。

### ④ 健康检查

```dockerfile
HEALTHCHECK --interval=20s --timeout=5s --start-period=60s --retries=5 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=3)" || exit 1
```

- Docker 每隔 20 秒问一次 `/health`。
- `--start-period=60s`：给应用 60 秒启动时间，这期间失败不算数（应用启动要建快表/巡检）。
- 健康状态会显示在 `docker ps` 的 `(healthy)` / `(unhealthy)` 里。
- 后面 compose 的 `depends_on: service_healthy` 就是靠它。

## 3. 动手：构建镜像

在项目根目录执行：

```powershell
docker build `
  -f deploy/Dockerfile `
  --build-arg PYTHON_IMAGE=docker.m.daocloud.io/library/python:3.13-slim `
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple `
  -t memory-backend:learn `
  .
```

逐个参数：

- `-f deploy/Dockerfile`：用哪个 Dockerfile。
- `--build-arg ...`：给上面 `ARG` 传值。国内网络直连 Docker Hub/PyPI 会失败，所以换镜像站；如果你能直连，可以省略。
- `-t memory-backend:learn`：给镜像起名 `memory-backend`，标签 `learn`。
- 最后的 `.`：**构建上下文**——把当前目录（项目根）作为「可复制文件的范围」发给 Docker。

### 构建时到底发生了什么

Docker 从上到下读 Dockerfile：

1. `FROM`：本地没有 `python:3.13-slim` 就去拉；
2. `COPY requirements-prod.txt`：从构建上下文根目录找这个文件，复制进镜像；
3. `RUN pip install`：在临时容器里执行 pip，执行完把结果保存成一层；
4. `COPY app`：复制代码；
5. 最后把各层叠起来，打上标签 `memory-backend:learn`。

你会看到输出里有 `[1/6]`、`[2/6]` 这样的编号——每一步就是一层。

### 构建上下文和 `.dockerignore`

`docker build .` 会把**当前目录**打包发给 Docker 守护进程。如果目录里有 `.env`、`data/`、`web/node_modules`，它们也会被发过去（很慢，而且可能把密钥带进镜像）。

项目的 `.dockerignore` 就是在说「这些不要发」：

```
.env
data
logs
bench
design
web/node_modules
web/dist
...
```

> 注意：`.dockerignore` 只影响「构建时能看到什么」，不影响容器运行时挂载什么。

## 4. 动手：运行容器

```powershell
docker run --rm -p 8000:8000 --env-file .env memory-backend:learn
```

逐个参数：

- `docker run`：用镜像启动一个容器。
- `--rm`：容器退出后自动删除（学习时不留垃圾）。
- `-p 8000:8000`：**宿主机端口:容器端口**。把宿主机的 8000 接到容器的 8000。
- `--env-file .env`：把项目根目录的 `.env` 注入容器。**密钥不在镜像里，是运行时给进去的。**
- `memory-backend:learn`：用哪个镜像。

启动后，另开一个 PowerShell：

```powershell
curl http://localhost:8000/health
```

应该返回：

```json
{"status":"ok"}
```

再看容器状态：

```powershell
docker ps
```

应该看到 `memory-backend:learn`，状态里有 `(healthy)`（刚启动时可能是 `(health: starting)`，等几秒）。

### 这个容器里没有 Redis / Qdrant，为什么还能起？

因为它们是软依赖。应用启动时连不上会降级：

- Redis 缺失 → 短期窗口为空，对话退化为单轮；
- Qdrant 缺失 → 语义检索跳过，结构化检索仍可用。

这就是「降级」的含义：**非核心能力关掉，主流程还能跑**。

### 镜像 vs 容器，用这一组命令体会

```powershell
docker images          # 镜像：模板，只读
docker ps              # 容器：模板跑起来的实例
docker stop <容器ID>    # 停容器；镜像还在
docker run ...         # 再启动一个新容器；镜像不变
```

改了代码后：

```powershell
docker build ... -t memory-backend:learn .   # 重新构建新镜像
docker run ... memory-backend:learn           # 新容器用新镜像
```

旧容器不会自动变——容器是「启动那一刻的镜像快照」。

## 5. 常见错误

| 报错 | 原因 | 解决 |
|---|---|---|
| `failed to resolve source metadata ... EOF` | 拉不到 Docker Hub | 加 `--build-arg PYTHON_IMAGE=docker.m.daocloud.io/library/python:3.13-slim` |
| `pip install` 卡住/超时 | PyPI 网络慢 | 加 `--build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` |
| `COPY failed: file not found` | 构建上下文不对 | 确认在项目根目录执行，最后的 `.` 不能少 |
| `Field required: LLM_API_KEY` | 没传环境变量 | `docker run` 加 `--env-file .env` |
| `curl: connection refused` | 容器没起来/端口没映射 | `docker ps` 看状态，`docker logs <容器ID>` 看报错 |
| `docker ps` 看不到容器 | 用了 `--rm` 且容器已退出 | 去掉 `--rm` 再看；或 `docker ps -a` |

## 7. 小练习（可选，但建议做）

1. 故意把 `-p 8000:8000` 去掉，再 `docker run`。`curl` 会失败——体会「容器内端口」和「宿主机端口」是两回事。
2. 改 `app/core/logging.py` 里一句日志文字，重新 build。观察输出：pip 那层用了缓存（`CACHED`），只有 `COPY app` 之后的层重建。
3. `docker run` 时不加 `--env-file .env`。观察启动报错，理解「配置是运行时注入的」。
