# 稀释实验：历史增长时谁会崩

## 一句话

**全上下文随历史增长线性崩塌到零，朴素 RAG 稳在四成，本系统全程稳在六到七成。**

## 设计

把 LoCoMo sample 0 的第 2 到 151 条（150 条，约 5,700 token）当作「有效历史」，
它的长度就是模拟的上下文窗口。然后不断追加**另一段对话**的内容当噪声。

窗口取「最后 150 条」，所以噪声追加多少，有效内容就被挤出多少：

- 追加 0 条 → 挤出 0%
- 追加 150 条 → 挤出 100%（窗口里一条有效内容都不剩）

三条件同题、同答案提示词、同判定口径：

| 臂 | 做法 |
|---|---|
| 全上下文 | 把窗口（最后 150 条）原样塞进 prompt |
| 朴素 RAG | 整段历史逐条 embedding，余弦取 top-5，不做重排 |
| 本系统 | 完整记忆链路（抽取 → 快表 → 语义粗排 → 逐张精筛 → 注入） |

题目：证据完整落在有效块内的 65 道正常题。

## 结果

| 历史条数 | 有效内容被挤出 | 全上下文 | 朴素 RAG | 本系统 |
|---|---|---|---|---|
| 150 | 0% | 63.1% | 38.5% | 64.6% |
| 175 | 17% | 55.4% | 41.5% | 73.8% |
| 200 | 33% | 43.1% | 41.5% | 70.8% |
| 225 | 50% | 30.8% | 43.1% | 67.7% |
| 250 | 67% | 23.1% | 35.4% | 69.2% |
| 300 | 100% | **0.0%** | 41.5% | 69.2% |
| 450 | 100% | **0.0%** | 43.1% | 63.1% |
| 600 | 100% | **0.0%** | 38.5% | 66.2% |

每格 n=65（1.5 个百分点/题，95% 置信区间约正负 11.6 个点）。

## 怎么读这张表

**全上下文是一条干净的滑坡，终点归零。** 有效内容被 100% 挤出后，窗口里只剩噪声，
它只能答「未提及」。这不是调参能救的，是「用窗口代表历史」这条路线的必然结局。

**朴素 RAG 不崩，但停在四成。** 它本来就检索整段历史，所以不受窗口挤出影响；
代价是基数低，比本系统低 25 到 30 个点。它在历史 4 倍时跌到 38.5%，说明噪声也开始
污染它的 top-5。

**本系统全程 63 到 74，波动都在噪声区间内。** 八档均值 68.1，标准差对 n=65 来说
不足以判定有系统下滑。历史涨到 4 倍时仍有 66.2%，与起点 64.6 基本持平。

## 成本对照

| 口径 | 全上下文 | 朴素 RAG | 本系统 |
|---|---|---|---|
| 生成侧 prompt token | 4,300 到 5,600 | 约 510 | 约 850 |
| **全链路 token** | 同上 | 同上 | **约 11,200** |

本系统的精筛每题 61 次判定，折合约 10,400 token，占端到端开销的九成以上。
这笔开销**不随历史增长**（候选预算封顶 60），但它是当前最大的一笔支出。

所以完整的说法是：**上下文成本是全上下文的一成半，端到端 token 是它的两倍。**
前半句是这张图要证明的，后半句必须一起写。

## 这个实验的边界

- 只有一段有效历史、一种噪声来源（另一段 LoCoMo 对话，说话人不同、话题相近）。
- 65 道题，单题 1.5 个点，小于 5 个点的差异不要解读。
- 「窗口」是按条数算的，不是按 token；因为两条来源的句子长度不同，全上下文臂的
  token 会从 5,600 缓降到 4,300。
- 全上下文在 100% 挤出时归零是构造使然，它说明的是这条路线在「历史远大于窗口」时
  不可用，不是它整体很弱。历史装得下的场合它依然是强基线（0% 挤出时 63.1%）。

## 复现

```bash
python dilution_prep.py                  # 生成有效块 + 噪声 + 题集
python ingest_dilution.py --noise 0      # 灌有效块
python run_dilution_eval.py --noise 0    # 三臂评测
python score_dilution.py                 # 打分汇总
```

八档全跑用 `run_levels.ps1`，增量灌库，总耗时约两小时四十分钟（含评测）。
