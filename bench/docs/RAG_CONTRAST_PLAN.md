# 因果链改动方案与验证方案

## 0. 一句话结论

**因果链现在不生效，主要原因不是边太少，是这条链在三个位置被先后切断。**

`led_to` 已经建了 90 条，覆盖全部 65 张事件卡。但一条边从「建出来」到「影响答案」，中间要过三道闸，现在三道全关着。

全文分两部分：第一部分是改代码让链活过来，第二部分是怎么验它真的活了。

---

# 第一部分 让因果链生效

## 1.1 链在哪三处断掉

以「小林辞职 → 三个月失眠 → 很累」这条两跳链为例，问题是「我为什么这么累」。

```
问题：我为什么这么累
   │
   ▼
① 实体倒排命中 165 张（占全库 290 的 57%）
   │
   ▼
② 纯余弦排序，截断到 60          ← 第一刀
   │     「小林辞职」和「为什么累」语义不像，余弦分低，
   │     排不进前 60，图在这里就没有起点了
   ▼
③ 顺线一跳                        ← 第二刀
   │     就算「累」活下来，也只能走到「失眠」；
   │     「辞职」要两跳，永远到不了
   ▼
④ 邻居卡单独送精筛                ← 第三刀
        模型只看到孤立的一张卡，判 low，
        边白建了
```

三处是串联的，任何一处不通，链都断。

**实测佐证**：精筛判定的档位分布是 high 10.5%、mid 16.1%、low 73.4%。顺线来的卡如果也被判成 low，图遍历就等于白走。

## 1.2 为什么「入口前移」不够

最直觉的改法是把 `_line_expand` 从截断之后挪到截断之前。这个改法单独做没有用。

挪到前面之后，会从 165 张出发，每张再带 3 个邻居，候选直接涨到几百张。然后仍然要用余弦截断，**而余弦照样会把「辞职」砍掉**。

绕一圈，问题原封不动，只是中间多花了算力。

## 1.3 改动一：让排序认识图

根本问题是排序函数只认「文本像不像」，不认「图上离多远」。

余弦分回答的是「这张卡和问题像吗」。「辞职」和「为什么累」本来就不像，它们的关系在边上，不在文本里。

改法：分数沿边传播，带衰减。

```
直接召回： score(card) = 余弦分

沿边继承： score(card) = max(
       自己的余弦分,
       max(所有父节点) score(parent) × 衰减系数
   )
```

举一个具体的数（设衰减 0.85）：

| 卡片 | 来源 | 分数 |
|---|---|---|
| 很累 | 直接召回 | 0.60 |
| 失眠 | 从「很累」跳一跳 | 0.60 × 0.85 = 0.51 |
| 辞职 | 从「失眠」跳两跳 | 0.51 × 0.85 = 0.43 |

截断阈值附近如果落在 0.4 左右，这条两跳的链就能活到精筛。

**要点是传播发生在截断之前。** 先算分，再截断，让顺着边过来的卡和直接命中的卡在同一条尺子上比。

## 1.4 改动二：深度从一跳改两跳

现在 `_line_expand` 只遍历一轮，最远到「种子 + 1 个邻居」，路径长度上限是 2。

两跳的链需要宽度为 2 的传播。改成按轮迭代：

```
第 0 轮：种子集（实体 + 语义 + 时间召回）
第 1 轮：种子的一跳邻居，分数 = 父分 × 衰减
第 2 轮：上一轮新增节点的一跳邻居，分数 = 父分 × 衰减
```

每轮只处理上一轮的新增节点（边界前沿），总计算量是「节点数 × 平均度数」，毫秒级。

**必须设每轮新增上限。** 否则第二轮可能从几十张扩到几百张。建议每轮最多新增 20 张，按分数取。

## 1.5 改动三：让精筛看见边

前两处改完，卡能活到精筛了，但第三处还在：模型看到的仍然是孤立的一张卡。

把来源渲染进去就够了，不需要改判定协议：

```
用户当前问题：我为什么这么累？
候选记忆卡片：小林连续三个月失眠
（这张卡由「小林辞职」顺着因果边引来）
```

成本是十几二十个 token，而且只对顺线来的卡加，每题最多十张，可以忽略。

**为什么不选另外两种做法**：

- **直接给高分**：绕过判定，风险最大。顺线会带来误连的邻居，全给高分等于拿图噪声挤那八个名额。
- **批量连边一起判**：信息最全，但踩过批量判定的坑。四张一批的档位一致率只有 84.3%，模型有系统性抬高 `high` 的倾向。这次批的是「父子对」，任务性质不同，漂移未必一样，但要做一致率实验才敢用。

单卡加来源是三者里改动最小、风险最低的。

## 1.6 三处的依赖关系

不能只改一处。

| 只改 | 会发生什么 |
|---|---|
| 只改排序 | 卡活到了精筛，但被单独判 low，还是不注入 |
| 只改深度 | 第一跳仍被余弦砍，深度再大也没有起点 |
| 只改精筛输入 | 链根本没走到精筛 |

顺序建议：先排序，再深度，最后精筛输入。三步做完一起跑。

## 1.7 落地位置

| 改动 | 文件 | 函数 | 规模 |
|---|---|---|---|
| 排序传播 | `retriever.py` | `_coarse_truncate` 之前新增一个 `_propagate` | 约 40 行 |
| 多跳 | `retriever.py` | 把 `_line_expand` 改造成按轮迭代 | 约 30 行，原来的一跳逻辑可复用 |
| 精筛带边 | `retriever.py` / `reranker.py` | `Candidate` 加一个来源字段；`_judge_one` 渲染时带上 | 约 15 行 |
| 参数 | `config.py` | 传播深度、衰减系数、每轮新增上限、K | 4 行 |

新增四个参数：

```
RETRIEVAL_PROPAGATION_DEPTH = 2      # 传播轮数
RETRIEVAL_PROPAGATION_DECAY = 0.85   # 每跳衰减
RETRIEVAL_PROPAGATION_FANOUT = 20    # 每轮新增上限
RETRIEVAL_COARSE_TOPK = 60           # 不变，只是截断时机挪到传播之后
```

## 1.8 成本影响

| 项 | 变化 |
|---|---|
| 精筛调用次数 | **不变**，截断仍到 60 |
| 传播计算 | 毫秒级，纯本地 |
| 精筛输入 token | 每题多约 200（10 张顺线卡 × 20 token） |
| 端到端延迟 | 基本不变 |

**这套改动不增加任何 LLM 调用**，它只是把同样的 60 个名额重新分配，让顺着边来的卡有公平的机会。

## 1.9 实施记录与回滚（2026-11-01）

三处改动曾经落地、单测通过、真实库跑通，**随后整体回滚**。

回滚理由有两条。

第一，收益接近零。LoCoMo 的多跳错题里，20 道有 15 道是「答了但漏」，只有 5 道是拒答。也就是说多跳的瓶颈是**枚举不全**，不是桥接缺失。图能传的边以 `led_to`（事件→实体节点）为主，传出来的多是实体描述卡，这类桥接实体倒排早就做到了。

第二，复杂度不划算。为了让传播真正生效，要额外维护传播轮数、衰减系数、每轮扇出、保底配额四个参数，还要在精筛输入里渲染来源。换来的是检索链路上又多一层需要调参的机制。

判断是：**结构化卡片的优势在检索侧，不在图侧。**

代码回到 `8b9e34d`，改动存在 `git stash`（消息「图传播实验」）。下面的记录保留，作为「做过、测过、否掉」的证据。

实施过程中撞到的那个坑值得记下来。

**第一版改完，传播等于没发生。**

真实库实测：每轮新增 12 到 20 张卡，但截断到 60 之后，**纯图卡只剩 0 到 1 张**。

原因是分数尺度不同。沿边衰减分（0.6 × 0.85 = 0.51，再乘 0.85 = 0.43）和余弦分混排，而前 60 名的余弦分都在 0.5 以上。图卡天然排在后面，全被砍掉。

**这说明「实现」和「生效」之间隔着一道我没预见的闸。** 如果没有跑真实库，只在单测里看「传播函数被调用了」，会误以为改动有效。

修法是给图卡留保底名额：截断时直连卡与图卡分开排序，图卡占 `RETRIEVAL_LINE_RESERVE`（默认 10，且不超过预算的三分之一）个位置。配额与分数尺度无关，这是它能起作用的原因。

改完之后实测每题的纯图卡稳定在 10 张。

**这个修法带来一个新风险，必须写进实验判读**：库里 90 条边绝大多数是「事件 → 节点」，所以传播最先拉到的是节点卡（`pottery workshop`、`mentorship program`），它们与问题话题相邻但未必是答案。保底 10 个名额可能挤掉本来该注入的卡。

实验 B 如果发现正确率下降，第一个要查的就是这里，处理方式是只给 `caused_by`（事件间因果）保底，`led_to`（指向节点）不占名额。

## 1.10 一个前提要先验证

改动成立的前提是：库里那 90 条边，连的确实是「需要跳一步才相关」的卡。

如果它们连的全是同主体、同语义的近邻（`Caroline is a runner` ↔ `Caroline runs every day`），那余弦本来就能把两端都召回，边是多余的。这时候传播再精巧，也只是多捞几张本来就能捞到的卡。

这个可以离线算，见第二部分实验 A。

# 第二部分 验证

## 2.1 实验 A：先验边有没有价值（不跑题，零成本）

**方法**：取每条边，算两端卡片正文的余弦相似度。

**读法**：

| 余弦区间 | 含义 | 该有的处理 |
|---|---|---|
| > 0.75 | 两端语义几乎相同，边是多余的 | 这类边占比高，说明图在重复语义检索已经做到的事 |
| 0.4 到 0.75 | 有关联但不直接 | 边缘价值，传播能带来增量 |
| < 0.4 | 字面毫不相干，只能靠边连上 | **真多跳边，图的价值全在这里** |

**输出**：90 条 `led_to` 和 4 条 `caused_by` 的三档分布。

**判定**：如果低于 0.4 的边不足 20%，说明这张图基本是语义检索的影子，改动一未必有效，先别动代码。

这一步十分钟，不用跑题，也不用调用模型。

## 2.2 实验 B：整链端到端（先整体，后拆刀）

改完三处之后，跑一次完整评测，看多跳题有没有涨。

**为什么不一开始就逐刀拆**：三个改动是串联的，单独拆任何一刀都注定没效果（见 1.6），拆了也读不出来。

**顺序**：先三处全上跑一次。

- 如果多跳明显涨了 → 再逐刀关掉做归因，值这个时间
- 如果没涨 → 假设被推翻，逐刀也没意义，直接转去查别的原因

**题集**：稀释实验的档 0，65 题，约十二分钟。多跳题在其中约三十道，一题 3.3 个点，够看出方向。

## 2.3 实验 C：对朴素 RAG 的四臂对照

四臂，2×2 因子设计。

|  | 无精排 | 有精排 |
|---|---|---|
| **朴素 RAG** | R1：消息级余弦 top-k | R2：RAG 加精排 |
| **本系统** | O1：图传播打分，不调精筛 | O2：完整链路 |

**行差**测结构的独立价值，**列差**测精排本身的价值，**交互项**测「结构是否让精排更有效」。

判读：

| 现象 | 结论 |
|---|---|
| 行差大、列差小 | 结构是主要贡献，精排可裁 |
| 列差大、行差小 | 精排是主要贡献，结构化是配角 |
| 交互为正 | 两者互补 |
| 打开精排后 RAG 追平 | 优势其实来自精排，卖点要改写 |

**两个必须先定死的细节**：

关掉精排会让实体路和顺线一起失效，因为只有语义路给候选打相似度分。所以 O1 臂必须给非语义候选一个兜底分，按入口固定：实体 0.60、时间 0.55、顺线 0.50、原文 0.45。

R2 臂不改精排一行：消息级取 top-60，包成候选，走同一个精排，取前八。这样两边都判 60 张，成本对齐。

## 2.4 实验 D：六个场景切片

用来回答「RAG 在哪些查询上结构性做不到」。语料自造，中文，三十条左右。

| 场景 | 对话形态 | 我们靠什么 |
|---|---|---|
| S1 跨时间因果 | 早说要去运动一整天，晚说累死了 | 同主体同时间窗的边 |
| S2 聚合计数 | 一周去了三次健身房 | 按实体枚举时间窗内的事件 |
| S3 先后顺序 | 三月辞职，五月搬家 | 卡片上的 `event_time` |
| S4 状态时效 | 三月住城西，七月搬城东 | 旧卡被取代下架 |
| S5 主体区分 | 两人有高度相似的表述 | 主语入卡 + 节点索引 |
| S6 多条件交集 | 去年夏天在杭州见的那个朋友 | 实体与时间两路过滤 |

每场景两题，共十二题。人工判分，命中实体即算对。

**硬要求**：链条两端不能有共同关键词。若两端都带「运动」，RAG 自己就能答对，这个场景作废。

## 2.5 判读表

| 实验 | 看什么 | 通过线 |
|---|---|---|
| A | 低余弦边占比 | 低于 0.4 的边 ≥ 20% |
| B | 多跳题正确率 | 比改动前涨 5 个点以上（152 题里约 8 道） |
| C | 四格正确率 | 至少一格出现「我们对 RAG 错」 |
| D | 六场景 | 至少四场景出现「我们对 RAG 错」 |

**三种反面情形要分开归因**：

- RAG 也全对 → 语料设计失败，两端太像，重做
- 我们也全错 → 能力确实不具备，记进局限
- 我们对但看不出用了边 → 可能靠语义碰对，检查注入段里有没有那张卡

# 第三部分 边界

**能证明**：至少存在一类查询，结构化记忆加图遍历能做到而朴素 RAG 做不到；精排的收益随候选变干净而变大。

**不能证明**：总体正确率更高；场景在真实分布上的占比；系统在所有任务上优于 RAG。

写进论文时这一节放在「方法对比」，不放在「总体性能」。措辞落在「存在一类 RAG 结构性无法处理的查询」，不要写成「本系统优于 RAG」。

**还有一个已知的边界要先说清**：即使三处都修好，多跳的深度上限仍然是 2 到 3 跳。链更长就需要更大的传播预算，而预算大了会稀释直接召回的卡。这个权衡在本文不做，留作后续。
