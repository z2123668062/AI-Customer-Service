## 明确不建议做的

| 想法 | 判断 |
|---|---|
| 完全删掉布尔实体匹配，只留语义召回 | 它当**筛选器**确实没用（命中率 63%，接近全选），但作为**召回通道**有语义路替代不了的东西：专名的字面精确性、Qdrant 挂掉时的降级保底。建议保留但降级为并列通道（见 #3），「纯语义」版本作为对照实验单独跑 |
| 把精筛换成向量相似度阈值 | 会丢掉「相关但已过期 → low」的治理语义，这是系统卖点 |
| 砍掉 L2 原文回填 | 单跳题靠它兜底 |
| 在检索端按「最近 N 张」硬截断 | 先按语义排序再截断，比按时间截断安全得多 |

## 建议的动手顺序

1. **先跑 #9**（一行、10 分钟、正确率应一字不变），验证延迟模型 `候选 ÷ 并发 × RTT` 对不对。
   对上了，说明 #1 的预测可信。
2. **再做 #1+#3**，同 50 题验正确率与注入卡片集合。这一步做完，一次实验从 25 分钟降到 6 分钟。
3. **然后 #2**（一行）和 **#4**（同题对照），这两项都能当天出结论。
4. **#5 单独排**，它要改写入契约，动之前先确认 `messages.created_at` 该记「会话发生时间」还是「入库时间」。
5. **#6~#8** 按需。
